Codex 配置与定制

\===========

Codex 提供丰富的配置选项，让你定制 Agent 的行为以适应不同的工作需求。

默认情况下 Codex App 会根据你的系统设置语言，如果没有可以通过 Settings（ 设置 ）：

Codex App 的设置

\-------------

打开方式：点击应用菜单中的设置（ Settings ），或按 Cmd + ,：

**常规（General）：**&#x914D;置文件的打开方式、命令输出在对话线程中的显示量。还可设置多行提示需要 Cmd+Enter 确认，以及防止任务运行期间系统休眠。

**通知（Notifications）：**&#x8BBE;置任务完成通知的触发时机，以及是否由应用主动请求系统通知权限。

!\[]\(<a href="https://www.runoob.com/wp-content/uploads/2026/03/8fa52738-fae3-4f52-b104-d189ae183812.png" target="_blank" rel="noopener noreferrer">https\://www\.runoob.com/wp-content/uploads/2026/03/8fa52738-fae3-4f52-b104-d189ae183812.png</a>)

**Agent 配置（Agent Configuration）：**&#x41;pp 中的 Codex Agent 与 IDE 和 CLI 扩展共享同一套配置。常用选项可在 App 内直接调整，高级选项需编辑 config.toml 文件（后文说明）。

!\[]\(<a href="https://www.runoob.com/wp-content/uploads/2026/03/a3072255-f88e-4046-af22-268666e05720.png" target="_blank" rel="noopener noreferrer">https\://www\.runoob.com/wp-content/uploads/2026/03/a3072255-f88e-4046-af22-268666e05720.png</a>)

**外观（Appearance）：**&#x652F;持选择基础主题，调整强调色、背景色和前景色，以及更换 UI 字体和代码字体。可将自定义主题分享给他人。

!\[]\(<a href="https://www.runoob.com/wp-content/uploads/2026/03/d5ad7055-f518-412e-86b3-cf3060d98624.png" target="_blank" rel="noopener noreferrer">https\://www\.runoob.com/wp-content/uploads/2026/03/d5ad7055-f518-412e-86b3-cf3060d98624.png</a>)

**Codex 宠物（Codex Pets）:**&#x53EF;选的动态陪伴角色，路径：\*\*Settings（设置） > Appearance（外观） > Pets（宠物）\*\*，可选择内置宠物或从本地 Codex 主目录加载自定义宠物。

!\[]\(<a href="https://www.runoob.com/wp-content/uploads/2026/03/runoob-1778053238310.png" target="_blank" rel="noopener noreferrer">https\://www\.runoob.com/wp-content/uploads/2026/03/runoob-1778053238310.png</a>)

**操作方式：**

\*   在输入框中输入 `/pet`

*&#x20;  使用&#x20;*\*Settings > Appearance\*\* 中的 **Wake Pet** 或 **Tuck Away Pet**

\*   按 `Cmd+K` / `Ctrl+K` 后运行同名命令

宠物悬浮窗可在使用其他应用时持续显示当前 Codex 工作状态（运行中 / 等待输入 / 待审查），并附有简短进度提示。

**自定义宠物（创建流程）：**

$skill\\-installer hatch\\-pet

安装后在命令菜单中选择 **Force Reload Skills**，再执行：

$hatch\\-pet create a new pet inspired by my recent projects

**Git**: 统一分支命名规范，配置是否启用强制推送（force push），并设置 Codex 自动生成提交信息（commit message）和 PR 描述时所用的提示语。

\### 配置合并规则

\*   项目配置覆盖用户配置

Rules（规则）

\---------

Rules 定义命令执行策略，控制哪些命令可以自动执行。

\### 规则文件

规则使用 Starlark 语言（类似 Python）：

规则定义

\----

\\# \~/.codex/rules/default.rules &#x20;

&#x20;&#x20;

\\# 允许 Git 命令 &#x20;

prefix\\\_rule( &#x20;

    pattern \\= \\\["git"\\], &#x20;

    decision \\= "allow", &#x20;

    justification \\= "Git commands are safe" &#x20;

) &#x20;

&#x20;&#x20;

\\# 禁止 rm -rf / &#x20;

prefix\\\_rule( &#x20;

    pattern \\= \\\["rm", "-rf", "/"\\], &#x20;

    decision \\= "forbidden", &#x20;

    justification \\= "Prevent system damage" &#x20;

) &#x20;

&#x20;&#x20;

\\# 询问 npm 命令 &#x20;

prefix\\\_rule( &#x20;

    pattern \\= \\\["npm"\\], &#x20;

    decision \\= "prompt", &#x20;

    justification \\= "npm may modify dependencies" &#x20;

) &#x20;

\### 决策类型

决策

行为

`allow`

自动批准

`prompt`

询问确认

`forbidden`

禁止执行

常见问题

\----

\### Q: 配置修改后如何生效？

修改配置后需要重启 Codex 才能生效。

\### Q: <a href="http://AGENTS.md" target="_blank" rel="noopener noreferrer">AGENTS.md</a> 应放在哪里？

项目根目录，或需要特殊规则的子目录。

\### Q: Skills 和 Rules 的区别？

Skills 定义任务执行逻辑，Rules 控制命令权限。

\### Q: 如何查看当前配置？

使用 `/status` 命令查看当前会话配置。
